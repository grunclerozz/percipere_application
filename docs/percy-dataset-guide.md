# Percy dataset guide (for the team)

Percy understands what a user says because we **train** it on example sentences. The more real
sentences the team writes, the better Percy gets. This guide says what to write and how to add it.
The training is a one-line command that the project owner runs after the team has added sentences.
**This week: add sentences, then we retrain.**

## Where the sentences go
- File: `data/percy/intents.csv` (the one source of truth). There is also
  `data/percy/percy-intent-dataset.xlsx` for typing in Excel; if you use it, **save/export as
  CSV (UTF-8)** and give the CSV to the project owner. Do not rename columns.
- One sentence per row. Columns:

| Column | What to write | Example |
|---|---|---|
| `text` | The sentence, as someone would **say** it | `pakibasa nga po` |
| `intent` | The meaning (pick from the list below, spelled exactly) | `read` |
| `author` | Your first name | `Ana` |
| `source` | Always `Team` | `Team` |
| `notes` | Optional: anything odd (borderline sentence, spelling) | `could also be select` |

## What makes a good sentence
- **Write how people really talk,** not how a textbook writes: Filipino, English and **Taglish**
  ("pwede mo bang i-read yan"), polite ("po") and casual ("basahin mo na").
- **Short and long:** "stop", "ihinto mo muna yan", "pwede bang tigilan mo muna ang pagbabasa".
- **Different words for the same thing:** basahin / read / pakibasa / simulan mo na.
- **Spoken spelling and speech-to-text mistakes are welcome.** The phone's microphone often writes
  "basahen" for "basahin" or "pillin" for "piliin". Add the mistake as it appears, and also the
  correct form.
- You do not have to say "Percy". The wake word is removed before Percy reads the sentence.
- **No personal information:** no real names of people, phone numbers, addresses, emails. Book
  titles and subjects are fine.
- Do not copy a sentence that is already in the file (the checker warns about duplicates).
- **Borderline sentences:** pick the best intent and say so in `notes`. The owner decides later.

## How many?
Aim for **at least 30 sentences per intent**, and mostly written by the team. Today there are
514 rows, but only 58 are the team's; the rest are starter sentences generated by Claude. Most
intents have only **8**, so start with these (the most needed):

| Priority | Intents with few sentences | Meaning |
|---|---|---|
| 1 | `read`, `pause`, `resume`, `stop`, `repeat` | Control the reading |
| 1 | `faster`, `slower`, `bigger_text`, `smaller_text` | Change speed or text size |
| 1 | `yes`, `no`, `open_item` | Answer a question; open a named book or document |
| 2 | `greeting`, `thanks`, `goodbye`, `out_of_scope` | Small talk; things Percy cannot do ("what time is it") |
| 2 | `report_issue` (18) | "I want to report a problem" |
| 3 | `where_am_i` (2 by the team), `previous_option`, `select`, `next_option`, `cancel`, `help` | Navigation: already around 35, but few from the team |

## The 27 intents and what they mean
| Intent | The user wants to… |
|---|---|
| `open_home` / `open_library` / `open_settings` | Go to Home / the Library (Aklatan) / Settings |
| `back` | Go back. **"bumalik" alone is `back`**; "bumalik sa home" is `open_home` |
| `next_option` / `previous_option` | Move to the next / previous item (in the Reader: next / previous sentence) |
| `select` | Choose the item they are on ("piliin", "yan na") |
| `cancel` | Cancel what is happening ("huwag na", "wag na", "cancel") |
| `help` | Ask what they can do or how it works |
| `where_am_i` | Ask which screen they are on |
| `read` / `pause` / `resume` / `stop` / `repeat` | Start, pause, continue, stop, or repeat the reading |
| `faster` / `slower` | Read faster / slower |
| `bigger_text` / `smaller_text` | Make the text bigger / smaller |
| `open_item` | Open something by name ("buksan mo ang Noli Me Tangere") |
| `greeting` / `thanks` / `goodbye` | Say hello / thank you / goodbye |
| `yes` / `no` | Answer a question from Percy. **Plain "hindi" or "ayoko" is `no`** |
| `report_issue` | Report a problem or idea |
| `out_of_scope` | Ask something the app cannot do (time, weather, singing) |

Two rules that are easy to mix up:
1. **"bumalik"** alone → `back`. **"bumalik sa home / library / settings"** → `open_home` /
   `open_library` / `open_settings`.
2. **"wag na" / "huwag na"** → `cancel`. **Plain "hindi" / "ayoko"** → `no`.

## Check and retrain (project owner)
1. Check the file (no changes made, just a report):

```powershell
scripts\percy\.venv\Scripts\python scripts\percy\validate_dataset.py
```

   It must say `No errors`. Warnings about "under 30" are expected until the team has added
   enough.
2. Retrain (this writes `assets/percy/model.json`, a report in `data/percy/reports/` and the
   Dart test vectors):

```powershell
scripts\percy\.venv\Scripts\python scripts\percy\train.py
```

3. Check that the app reads the new model exactly like Python:

```powershell
flutter test test/core/percy/intent_classifier_test.dart
```

4. Read the new report in `data/percy/reports/` (accuracy per intent, mistakes). If one intent is
   often confused with another, add more sentences to **both**, with clear differences.

One-time setup of the Python environment and how the model works: `scripts/percy/README.md`.
Design and rules: `docs/specs/percy-local.md`. The app can also export what users actually said
(Settings, developer builds, "Export Percy's log (CSV)"); rows from that log come with
`source = STT log` and are very valuable, but check each one before adding it.
